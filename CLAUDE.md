# Working in this repo

## The apply workflow

Changes to this config are **never built locally**. The correct cycle is:

```
edit modules/ → nix run .#write-flake (if needed) → commit → git push → wait for CI → nixos-rebuild switch
```

1. **Edit** the relevant aspect file(s) under `modules/`.
2. **Regenerate `flake.nix`** if you added, removed, or changed any `flake-file.inputs` declarations in a module:
   ```console
   nix run .#write-flake
   ```
   `flake.nix` is auto-generated — **never edit it directly**. The file says so at the top.
3. **Commit and push** to `master`. GitHub Actions (`build-systems.yml`) builds the `hornicorn` system closure and pushes it to Cachix automatically.
4. **Apply on the machine** once CI goes green:
   ```console
   sudo nixos-rebuild switch --flake github:blessuselessk/lul#hornicorn
   ```
   This pulls the pre-built closure from `lul.cachix.org` rather than building locally. The Cachix substituter is already configured in `flake.nix`'s `nixConfig`.

## flake.nix is generated

`flake.nix` is written by `nix run .#write-flake`, which reads `flake-file.inputs` declarations scattered across `modules/*.nix`. It must be regenerated (and the result committed) whenever a module adds or removes a flake input. Running `nix flake lock` afterward cleans up `flake.lock` to match.

If you remove or park a module that declared inputs, run both:
```console
nix run .#write-flake
nix flake lock
```

## Parking a module without deleting it

Move it into `modules/_disabled/`. `import-tree` ignores any path containing `/_`, so the file stays in git but contributes nothing to the build. If the module had `flake-file.inputs` declarations, run `write-flake` + `nix flake lock` after moving it.

## ci-runtime.nix

`modules/ci-runtime.nix` is committed with `CI = false` (its default). CI injects a `CI = true` override at build time. Do not edit this file to change runtime behaviour — it exists solely to let modules gate hardware-specific assertions on the CI context.

## Host

Single host: `hornicorn` (ThinkPad P14s Gen 2i). Intel Xe2 iGPU (primary display), NVIDIA T500 dGPU (PRIME offload). NVIDIA driver is proprietary (stable, currently 595.58.03).

## Dendritic pattern quick reference

- **One file per feature** under `modules/` — aspect name matches the file name.
- **Two classes per aspect**: `nixos` (system) and `homeManager` (per-user).
- Add a feature: write `modules/foo.nix` declaring `den.aspects.foo`, then add `den.aspects.foo` to the `includes` list in `modules/hosts/hornicorn.nix`.
- **Never edit `hardware-configuration.nix`** by hand — it's the machine scan output.
- See `README.md` for a fuller pattern explanation.
